# Company pilot interface v1

All endpoints live under `/api/accounts`. Current account cookie or `Authorization: Bearer tpm_...` authenticates a real account. Active membership is assigned; never accept a demo identity or client role. `POST /switch {membershipId}` selects assigned workspace. Every pilot action supplies workspaceId matching that current membership.

## Pilot API
`GET /pilot`: `{network:'testnet',chainId:number,token:string,workspaceId:string,ready:boolean,treasury:{address:string,balance:number}|null,departments:[{id,name,address,balance,headMembershipId?:string}],vendors:[{id,name,address}],cards:[{id,departmentId,membershipId,name,keyAddress,cap,allowedVendorIds:string[],active:boolean,tx?:string}],requests:[{id,departmentId,membershipId,cardId,vendorId,amount,note,status:'held'|'paid'|'declined',reason?:string,tx?:string}],receipts:[{id,kind,departmentId?:string,membershipId?:string,amount?:number,tx,at}],operations:[{id,action,status,error?:string,tx?:string}]}`. Views scoped by current role; employee only own cards/requests/receipts, lead own department, Finance/owner company. Addresses are testnet. Built-in test vendors are workspace-specific derived addresses; no actual merchant receives real value.

`POST /pilot/actions`: `{workspaceId,requestId:UUID,action,...fields}` returns `{status:'confirmed'|'held'|'pending'|'failed',operationId,tx?:string,message?:string}`. Same requestId and identical payload resumes original operation; conflicting payload=409. Pending/unknown must reuse id. Clients persist pending payload before send and expose retry, not silently create another payment.

Actions:
- provision: owner/Finance, initial test treasury funding (10000 test dollars, once per workspace).
- fund: owner/Finance, `{departmentId,amount}` transfers treasury→department.
- delegate: owner/Finance, `{departmentId,membershipId}` assigns active same-department lead an admin key; initially one lead, replacement requires revocation strategy (do not silently leave old authority active).
- issue: delegated lead only (or Finance root if intentionally specified by backend), `{departmentId,membershipId,cap,allowedVendorIds}` cap per 30 days and nonempty vendor allowlist. Active same-dept employee/contractor/lead card holder; reject duplicate active card or rotate safely.
- spend: card owner, `{cardId,vendorId,amount,note}`. Known limit/recipient rejection creates held request; unknown transport outcomes remain pending.
- approve / decline: delegated lead own dept or Finance/owner, `{heldId}`; cannot approve own request by userId even via second membership. Amount>1000 Finance only. Approve pays once with authorized department signer.
- revoke: lead own dept or Finance/owner, `{cardId}` revokes on chain; app stops signing immediately while pending.

## Backend adapter contract
Backend exports `PilotAdapter` and other shared types in pilot-types.ts; driver implements pilot-tempo.ts. `addresses(workspaceId,departmentId?,membershipId?,cardId?)` synchronously returns `{treasury,department?,headKey?,cardKey?}`. `vendors(workspaceId)` returns deterministic test vendors. `balances(addresses:string[])` returns address→number. `prepare(command)` performs reads/estimate/sign only and returns serializable `{raw:string,hash:string}`. `submit(prepared)` broadcasts identical bytes and returns `{status:'confirmed'|'reverted'|'pending',tx:string,error?:string}`; receipt must be checked before success. `status(prepared)` reconciles only. `command` includes workspaceId,operationId,action, departmentId?,membershipId?,headMembershipId?,cardId?,amount?,cap?,vendorAddresses?,to?,note?. All network, chain ID and token checks fail closed. Adapter must not use the demo ledger or mainnet.

Backend `registerPilotRoutes(app,store,adapter,auth)` auth is `(directory,context,workspaceId?)=>{user,session,m}`; root supplies real member function. Directory has optional `pilot?: PilotLedger` field added by root. Async network calls MUST NOT occur inside `store.change` callbacks (CAS retries). Persist claim, signed transaction and outcome separately. Serialize each workspace's unresolved spending operation; never create a new transfer after ambiguous broadcast. Known estimate rejection can create held request. Preparation failures are retryable only when no signed bytes persisted. Membership edits must be blocked when an affected active delegation/card exists until revoked, or atomically queue revocation; root will integrate backend helper for that.

## Expo Go pairing (no native passkey module)
POST `/mobile/start {}` unauthenticated returns `{deviceId,pollingSecret,userCode,verificationUrl,expiresAt}`. Phone opens verificationUrl in system browser via Linking. Browser user signs in/creates company through existing passkey UI, then explicitly approves phone code. GET `/mobile/preview?deviceId=...&code=...` returns code/expiry (authenticated). POST `/mobile/approve {deviceId,userCode}` requires browser cookie and same origin. POST `/mobile/poll {deviceId,pollingSecret}` returns `{status:'pending'|'approved',token?:string,expiresAt?:number}`. Token is only delivered to phone secret holder; no bearer tokens in URLs. POST `/logout` revokes current session. Native token SecureStore; web test storage origin-scoped; restore verifies server session. `/session` and `/workspace` shapes unchanged. Server membership is source of names/roles. On authentication change clear stale workspace/requests. Auth on native accounts calls sends same-origin Origin header; root middleware supports native bearer auth. Start/poll permitted without browser origin, no credentials.

## UI
Real companies are default in native; preserve separate demo as explicit optional route. Use existing system-theme/Geist/spacing/components. Real permissions never chosen by user. Native supports workspace switching, setup/invitations, provision/fund/delegate/issue/spend/approve/decline/revoke and explorer receipts. Browser pairing panel in Workspace reads `?device=...&code=...`, survives sign in/create and has explicit approve button. Payment controls show testnet and test money. No privacy or mainnet claims.
